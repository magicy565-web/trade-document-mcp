## V0.1 工程验证

在干净 checkout 里执行。两次运行分别使用锁定依赖的隔离环境。Pytest 包含真实 stdio 调用、32 条逐条编写的业务回归，以及数值、证据、版本、权限、归档和渲染测试。验证命令同时运行合成冒烟测试和四类单证演示。

```sh
uv run --no-project --python 3.11 --with-requirements requirements.lock --with-editable '.[test]'   python tools/verify_v01.py --python 3.11 /tmp/trade-v01-evidence-311
uv run --no-project --python 3.12 --with-requirements requirements.lock --with-editable '.[test]'   python tools/verify_v01.py --python 3.12 /tmp/trade-v01-evidence-312
```

每次选择一个新的输出目录。`verification.json` 记录提交、源码树、依赖锁摘要、解释器、日志及样例哈希。合并前以 PR 实际审核的提交为准。

32 条业务回归使用固定预期金额或阻断原因。它们使用虚构买卖资料和共同的默认草稿，仍待独立标注和专业审核。`tools/evaluate.py` 中的 100 个输入由同一订单派生，作为冒烟回归运行。真实一次通过率和字段准确率需要独立数据。

示例签名在本地使用临时虚构审核人。样例完整性由服务端审单核对，视觉审核由专业单证员依路线图签核。法域规则、正式报关及企业模板族的准确率需分别按后续阶段验收。

## 已知边界

- V0.1 的企业工作簿输入为三处标记的单页结构。公式支持明细和汇总，任意企业模板适配在 V0.3 验收。
- 日文及常见汉字、英文和常见拉丁字符有基础 PDF 支持。超出字库的内容需要人工确认，回读审核会报告丢失文本。
- 旧版本可以重新预览。此前的签名请求需要用新预览重新签署。已归档文件仍可回读检查。
- GitHub 既有托管任务因账户账单锁定未启动。验收使用可复现的双环境记录。
